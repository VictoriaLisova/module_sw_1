# Модульна контрольна робота

**Дисципліна:** Semantic Web
**Варіант:** 1

## Опис

У роботі виконано два завдання:

1. Побудова RDF-графа на основі таблиці авіарейсів та збереження його у форматі Turtle.
2. Виконання трьох SPARQL-запитів до Wikidata та збереження результатів у CSV-файли.

## Використані технології

* Python
* Pandas
* RDFLib
* Requests
* RDF / Turtle
* SPARQL
* Wikidata

## Завдання 1 — Побудова RDF-графа

Скрипт `build_graph.py` читає таблицю `flights.csv` та параметри з `params.json` і формує RDF-граф.

### Запуск

```bash
python build_graph.py flights.csv params.json graph.ttl
```

Результатом роботи є файл:

```text
graph.ttl
```

### Namespace

Для всіх ресурсів використовується namespace:

```text
http://example.org/mkr/
```

з префіксом:

```text
ex:
```

### Класи

У графі використовуються класи:

* `ex:Flight`
* `ex:Airline`
* `ex:City`
* `ex:Country`
* `ex:BudgetFlight`
* `ex:LongFlight`

`BudgetFlight` та `LongFlight` є підкласами `Flight`.

### Дані про рейси

Для кожного рейсу створюється ресурс:

```text
ex:flight/<ID>
```

Для рейсу зберігаються:

* авіакомпанія;
* місто відправлення;
* місто прибуття;
* країна міста;
* дата відправлення;
* тривалість;
* ціна.

Дата зберігається як `xsd:date`, тривалість — як `xsd:integer`, ціна — як `xsd:decimal`.

### Нормалізація даних

Перед побудовою графа виконується:

* видалення зайвих пробілів;
* приведення ID рейсу до верхнього регістру;
* приведення назв міст до формату `title()`;
* заміна пробілів на `_`;
* приведення дат до формату `YYYY-MM-DD`;
* видалення дублікатів рейсів після нормалізації ID.

Якщо ціна рейсу відсутня, властивість `priceEur` для нього не створюється.

### Класифікація рейсів

Тип рейсу визначається відповідно до параметрів із `params.json`:

* `BudgetFlight` — якщо ціна не перевищує заданий поріг;
* `LongFlight` — якщо тривалість не менша за заданий поріг;
* `Flight` — якщо рейс не відповідає жодній з двох умов.

### Затримки

Для затримок створюються окремі RDF-ресурси типу `rdf:Statement`.

Наприклад:

```text
ex:stmt/FL-6146-delay
```

Інформація про затримку містить:

* рейс;
* властивість затримки;
* кількість хвилин;
* джерело інформації.

### Країни з частими вильотами

Для рейсів, що вилітають із країни, з якої здійснюється щонайменше два рейси, додається:

```text
ex:fromBusyCountry true
```

## Завдання 2 — SPARQL та Wikidata

Для виконання завдання використовується Wikidata SPARQL endpoint.

### Мій варіант

Номер у списку:

```text
N = 18
```

Залишок від ділення на 6:

```text
18 mod 6 = 0
```

Тому використано такі параметри:

| Параметр    | Значення                         |
| ----------- | -------------------------------- |
| Клас        | `Q1248784` — аеропорт            |
| Країна      | `Q183` — Німеччина               |
| Властивість | `P2044` — висота над рівнем моря |
| Поріг       | `100`                            |

### SPARQL-запити

Створено три запити:

* `q1.rq` — пошук аеропортів із висотою понад 100 м та їхніх офіційних сайтів;
* `q2.rq` — пошук регіонів із найбільшою кількістю аеропортів;
* `q3.rq` — визначення населення регіонів, у яких розташовані аеропорти.

### Запуск

Для виконання запитів використовується пакет `requests`.

Встановлення:

```bash
pip install requests
```

Запуск:

```bash
python run_queries.py
```

Скрипт надсилає запити до:

```text
https://query.wikidata.org/sparql
```

заголовком:

```text
User-Agent: mkr1/1.0
```

### Результати

Після виконання створюються:

```text
q1.csv
q2.csv
q3.csv
```

Також створюється файл:

```text
meta.json
```

у якому зберігається час отримання результатів:

```json
{
  "retrieved_at": "<дата й час>"
}
```
